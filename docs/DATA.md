# Data, provenance and evaluation protocol

## Two sources, never silently mixed

1. **UNSW-NB15:** historical laboratory network flow records. The full dataset
   comprises 2,540,044 records across four headerless CSVs. The published
   classification subsets have 175,341 and 82,332 records.
2. **Synthetic demonstration:** deterministic records generated by our own
   program. Every event carries `is_synthetic=true` and source `Synthetic
   demonstration`. They verify behavior; their detection accuracy has no
   scientific meaning.

The university page provides the authoritative description and bibliography:
https://research.unsw.edu.au/projects/unsw-nb15-dataset

## Downloading

The university's dataset link redirected to Microsoft sign-in during this work.
`python run.py download --mirror` explicitly uses a public copy at:
https://github.com/jamshaid120/UNSW_NB15-Complete-dataset

The commit is pinned to `161024104f19eea98b5c9aba0499a8fcb867ba1d`.
Git LFS data, rather than LFS pointer text, is downloaded. A checksum mismatch
aborts the download. The provenance manifest records URLs, original filenames,
the commit, SHA-256 hashes, row counts and download time.

**Important naming discrepancy:** this mirror calls its 175,341-row file
`UNSW_NB15_testing-set.csv` and its 82,332-row file
`UNSW_NB15_training-set.csv`. We normalize the 175,341-row file to `train.csv`
and the 82,332-row file to `test.csv`, matching the sizes described by UNSW.
The mapping is explicit in `cyberwatch/datasets.py`; it is not a claim that
the mirror's bytes have been independently authenticated by the university.

To avoid the mirror, obtain the CSVs from the university and place the intended
splits at `data/raw/train.csv` and `data/raw/test.csv`, or pass explicit paths.
Headered split CSVs and the four 49-column headerless CSVs are supported.

## Canonical event

An event includes a stable `event_id`, `event_time`, `source`, split and source
file, protocol/service/state, 21 numeric traffic measurements, optional
addresses, ground truth, and explicit provenance flags. Exact input features
are exposed as `FEATURE_NAMES` in `cyberwatch/schema.py` and stored with models.
The 21 numeric features are log-transformed with `log1p`; categorical values
use fixed one-hot vocabularies with an `other` bucket. This does not fit any
preprocessing on the held-out sample.

The headerless files include source/destination addresses and start time.
The split CSVs do not: we **do not fabricate IPs or original chronology**.
Instead, addresses are null and `time_is_simulated=true`. Replay emits
completed connection records, not a live packet capture or packet-time detector.

IDs derive from source filename, row position and raw content. Replaying the
same source file deduplicates. Renaming a source file changes this identity,
so preserve canonical filenames when replaying the same dataset.

## Quality gates

Required strings must be present. Numeric detector inputs must be finite and
non-negative. Event time must parse with a timezone in the local contract.
Optional labels must be 0 or 1. Invalid JSON/events go to quarantine in Spark;
invalid JSONL syntax is reported immediately by the local file reader.

Spark stores raw input first, writes quarantine, then blocks silver/gold
publication if the rejected fraction exceeds `--max-reject-ratio` (default 5%).
The gate uses **records in the current micro-batch**, not all historical rows.
A failed batch retains its checkpoint offsets for retry. A persistent bad batch
must be corrected or explicitly allowed with a justified threshold.

## Evaluation

`run.py train` rejects identical training/evaluation files. It removes training
rows whose exact engineered feature vector occurs in the evaluation file,
then fits a seeded 64-tree random forest. It does not use label, attack
category, ID, IP address, filename, split, or timestamp as an input feature.

There is no hyperparameter selection or threshold tuning on evaluation labels.
The model uses a fixed 0.5 threshold. Precision, recall, F1, balanced accuracy,
ROC AUC, average precision and the confusion matrix are exported. A probability
parity check compares portable JSON inference with scikit-learn on 200 held-out
records. JSON trees avoid loading an arbitrary pickle into the dashboard.

This exact deduplication addresses one leakage route, but does not make the
original split a temporal, organization-independent or attack-campaign-independent
benchmark. Rare categories, class imbalance, old lab traffic and domain shift
remain limitations. Binary detection does not identify the exact attack family.
High `sttl` importance can reflect capture-environment artifacts, so operational
generalization should be investigated rather than assumed.
